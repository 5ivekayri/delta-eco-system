# Demo и приёмка Delta v0.1

## Подготовка

1. Настройте `.env` по README, запустите `docker compose up --build -d`.
2. Установите Whisper и Piper по [VOICE_PIPELINE.md](VOICE_PIPELINE.md), перезапустите Core.
3. Откройте http://localhost:8080 и сохраните `DELTA_TOKEN` в Settings.
4. Выполните `uv run python scripts/seed_demo.py`. Скрипт обращается к Core и Tasks
   через gateway, не подключается к их БД. Добавляет отсутствующие пространства
   Master Thesis / Dark Weather и задачи Prepare API tests / Finish architecture /
   Add device agent. Повторный последовательный запуск не создаёт дубликаты по
   имени/названию без учёта регистра; существующие описания и статусы сохраняются.
   Не запускайте seed параллельно. При достижении лимита списка Tasks (1000)
   скрипт останавливается, чтобы не создавать непроверенные дубликаты.
5. Виртуальные датчики создаёт миграция: 23 °C, 30%, движение есть, свет выключен.
   Seed не сбрасывает уже изменённый свет. Онлайн-устройства не подделываются.

## Сценарии

| Сценарий | Действие | Ожидаемый результат |
| --- | --- | --- |
| Устройство | Запустить Agent по README, затем остановить | Devices и Overview показывают online, затем offline; Activity содержит переходы |
| Голос → задача | Assistant → Голос → «Добавь задачу протестировать API» → остановить | Транскрипция, один tasks.create, текст и звук; задача видна в Tasks, workflow в Activity |
| Локальный маршрут | Developer mode → «Покажи устройства» | Local route, один вызов инструмента, 0 LLM-запросов |
| Пространство | Создать привязку Dark Weather к online-устройству с разрешённым каталогом; выбрать устройство в Assistant; «Открой Dark Weather» | Каталог/приложения/сайты открываются на выбранном хосте, видны фактические результаты |
| IoT | «Включи рабочий свет», затем «Какая температура?» | Свет меняется в Virtual IoT, температура 23 °C; свет сохраняется после перезапуска |
| Сервис | Открыть Services | Delta Tasks online, доступные инструменты; health проверяется каждые 15 секунд |
| Сбой озвучки | Заблокировать autoplay в браузере | Доступна кнопка прослушивания; повтор звука не повторяет действие |
| Ошибка токена | В новой сессии сохранить неверный token | Ошибка защищённых API; интерфейс не выдаёт её за отсутствие пользовательских данных |

Привязки к каталогам создаются вручную: seed не знает ваши реальные пути и не
запускает приложения. Отключённое устройство или отказ Agent не должны отображаться
как успешный запуск. OpenRouter остаётся fallback для сложных запросов, его задержки
и доступность зависят от настроенного провайдера.

## Воспроизводимые проверки

```sh
uv run --extra test pytest -q
uv build
cd apps/delta-control-center
npm test
npm run build
DELTA_UI_URL=http://127.0.0.1:8080 npm run test:e2e -- --workers=1
```

Из корня, при запущенных сервисах:

```sh
uv run python scripts/smoke_devices.py
uv run python scripts/seed_demo.py
uv run python scripts/seed_demo.py
uv run python scripts/smoke_voice_task.py path/to/task-command.wav
```

Последний скрипт требует WAV с командой создания задачи. Проверяет реальный STT,
локальную маршрутизацию, запись Tasks, PCM WAV от Piper и TASK_CREATED в Activity;
удаляет только задачу с ID, полученным в ответе. При потере HTTP-ответа сначала
проверьте историю и Tasks: автоматический повтор изменяющего запроса небезопасен.
Тесты браузера читают development token из локального `.env`; не запускайте их
против пользовательской production-инсталляции.

## Фактическая проверка — 2026-09-27

- 168 backend-тестов; production frontend и Python wheel/sdist собраны.
- Реальный macOS Host Agent: регистрация, system_info, heartbeat и offline после остановки.
- Seed: первый запуск добавил 2 пространства и 3 задачи, второй — 0 и 0.
- Whisper small → локальный tasks.create → Piper → Task API / Activity: 5279 ms
  server total (STT 4169, local router 5, tool 14, TTS 1008 ms), 0 LLM-запросов.
  Использован синтетический русский WAV из benchmark-корпуса; задача удалена после проверки.
- Core и UI пересобраны и запущены на существующем PostgreSQL volume без сброса данных.

## Границы проверки

Чистый Compose-запуск с пустыми volumes проверен отдельно (см. ниже), используя
уже собранные образы. Загрузка моделей в новом окружении не выполнялась;
установка моделей описана отдельно. Физический микрофон/динамики,
Safari/Firefox и реальные Windows/Linux-хосты требуют ручной приёмки.
Windows/Linux-адаптеры покрыты mocks. Запуск GUI-приложений и каталога на вашем
устройстве проверяется вручную после задания привязки. Полный переносимый релиз
нельзя считать подтверждённым только по локальным автоматическим тестам.

Браузерная проверка: 23 сценария полного прогона и дополнительная проверка
соответствия Overview реальным API — все 24 прошли. Frontend unit test также прошёл.
Скриншоты desktop/mobile проверены; горизонтального переполнения на ширине 390 px нет.

## Проверка пустых volumes — 2026-09-27

```sh
uv run python scripts/check_clean_install.py
# Если Docker вне PATH: добавьте --docker /absolute/path/to/docker
```

Нужны ранее собранные стандартным `docker compose build` образы `delta-*`,
Compose >= 2.24.4 и свободные порты 18000/18080. Скрипт использует отдельный
случайно названный проект, сеть и новые volumes; создаёт независимые credentials
в `.runtime/<project>/acceptance.env` с правами 0600. Не использует OpenRouter.

Проверено за 23.44 секунды: инициализация PostgreSQL и миграции Core/Tasks,
здоровье сервисов, авторизация, пустые списки, значения IoT, seed и отсутствие
дубликатов, manifest discovery, локальная команда Assistant к Tasks,
сохранение пространств и задач после перезапуска. При пустом кеше Whisper
возвращается явная STT_UNAVAILABLE; подмена распознавания mock-ответом отсутствует.
Загрузка моделей и реальный голос в этом отдельном окружении не проверялись.

Контейнеры и сеть тестового проекта останавливаются и удаляются в finally;
его volumes оставлены для диагностики. Основной проект `delta` не затрагивается.
Отчёт и лог лежат в `.runtime/<project>/report.json` и `compose.log`.
