# Создание рабочих пространств через Assistant

Текст и голос используют единый AssistantService. В режиме OpenRouter модель
получает зарегистрированный инструмент `workspaces.create` с JSON Schema.
Локальный классификатор не подменяет LLM для создания пространств.

## Использование

В Workspaces нажмите «Открыть Assistant», затем микрофон. Например:

- «Создай рабочее пространство Диплом».
- «Создай рабочее пространство Учёба с описанием Подготовка к экзаменам».
- «Создай рабочее пространство Исследование с браузером на этом компьютере
  и сайтом https://example.com» (предварительно выберите текущее устройство).

Название обязательно, описание необязательно. Если имени или целевого устройства
для привязки не хватает, модель должна задать уточняющий вопрос. Предыдущие
сообщения и результаты инструментов остаются в общем контексте разговора.
Пути и адреса должны исходить от пользователя, UUID — из реестра устройств.
Без привязки устройство не требуется. Создание не запускает приложения и не
создаёт каталог на диске. Запуск — отдельный инструмент `workspaces.launch`.

## Контракт

`workspaces.create`: `{name, description?, binding?}`. Binding использует
существующий контракт: `{device_id, local_path?, apps?, urls?}`. Разрешённые apps:
`vscode`, `browser`; URL проходят существующую проверку HTTP(S). Привязка должна
содержать хотя бы одно действие. Неизвестные поля отклоняются.

Результат содержит ID, название, описание и список bindings. Пространство,
необязательная привязка и событие `WORKSPACE_CREATED` сохраняются одной
транзакцией. Неизвестное устройство или ошибка привязки не создают пространство.
Повторное название отклоняется (`WORKSPACE_EXISTS`); существующий объект не
перезаписывается. REST POST /api/v1/workspaces использует ту же бизнес-логику.
Новых переменных окружения и миграций не требуется.

## Проверки и ограничения

`tests/test_workspace_assistant.py` проверяет текст, аудиозапрос с подставленным
STT и LLM, сохранение привязки/истории, дубликаты, отсутствие имени, неверные
параметры и невозможность заявить о создании без вызова инструмента.
Mock LLM поддерживает только простой пример с названием; свободные формулировки,
описание, привязки и уточнения требуют настроенного OpenRouter.
Распознавание реального микрофона и точность извлечения параметров зависят от
установленного STT и выбранной модели. Автотест с подставленным STT не проверяет
акустическое качество. Отказ TTS не отменяет сохранённое пространство.
