# Документы DOCX

Раздел «Документы» в Control Center позволяет загрузить Word-файл до 10 МБ,
прочитать основной текст и ячейки таблиц, вручную изменить абзацы или добавить
абзац в конце. Скачивание возвращает выбранную версию DOCX. Исходник хранится
побайтно, каждая запись создаёт новую неизменяемую версию. Это текстовый редактор,
не точная постраничная визуализация Word.

ИИ отвечает на вопросы по документу и предлагает изменения. Пользователь выбирает
абзацы флажками; без выделения отправляется весь основной текст. Предел контекста
16 000 символов с разметкой: большие документы требуют выделить меньший фрагмент.
В запрос не включаются чужие документы, история общего чата, изображения,
колонтитулы и примечания. Содержимое документа считается данными, а не инструкциями.
Запрос использует текущий provider Delta (OpenRouter, local или auto через bridge).
Интерфейс предупреждает о передаче текста облачной модели. Сам файл не передаётся
LLM. Ответ модели не сохраняет файл: сначала отображается «Было / Станет», затем
пользователь нажимает «Применить и сохранить». Предложения можно отклонить.

Предложения проходят отдельный ToolRegistry с единственным инструментом
`documents.propose_changes`, Pydantic-валидацию, проверку выбранных абзацев и
совпадения исходного текста. Shell, пути и глобальные инструменты не доступны.
Редактирование по ИИ поддерживает только выделенные текстовые абзацы и добавление
текста в конце; длинные ответы ограничены лимитом настроенной модели. Ошибку или
некорректный ответ нужно исправлять новым более узким запросом; файл не меняется.

При сохранении изменяется только word/document.xml. Остальные ZIP-части DOCX
остаются побайтно прежними (изображения, стили, колонтитулы, relationships).
Изменённый простой абзац сохраняет стиль и формат первого фрагмента; разное
начертание внутри этого абзаца объединяется. Абзацы с полями, гиперссылками,
рисунками и другими сложными встроенными объектами доступны только для чтения.
Колонтитулы и примечания не редактируются. OCR и редактирование разметки страниц
не входят в эту версию. Форматирование страниц может измениться при изменении
длины текста; финальное оформление проверяйте в Word/LibreOffice.

## Хранение и доступ

Таблицы Core `documents` и `document_versions` создаёт миграция 0007. Данные и
версии хранятся в базе Core; границы базы Tasks не пересекаются. В режиме аккаунтов
доступ ограничен владельцем документа и существующими admin-сессиями. В dev-режиме
используется существующий bearer-token и общий владелец development. Обновление
ревизии — атомарный UPDATE с проверкой старого номера; конфликт возвращает 409.
Резервная копия Core DB включает все версии; отдельно копировать файлы не нужно.
Удаление документов и квоты хранения пока отсутствуют: учитывайте рост базы.

## API

- GET /api/v1/documents — документы текущего владельца (последние 200).
- POST /api/v1/documents — multipart file (.docx).
- GET /api/v1/documents/{id}?revision=N — текст и список версий.
- GET /api/v1/documents/{id}/download?revision=N — DOCX.
- PUT /api/v1/documents/{id} — base_revision, edits[{block_id,old_text,text}], append[].
- POST /api/v1/documents/{id}/ask или /propose — revision, instruction, block_ids[].

Документы ограничены 2000 ZIP-частями, 40 МБ распакованного содержимого и 10 000
абзацами. До multipart/JSON-парсинга действует предел HTTP body, включая chunked.
Зашифрованные архивы, макросы, встроенные объекты, XML DTD/entities и дубликаты
ZIP-частей отклоняются. Внешние ресурсы документа не загружаются. Имена файлов
не используются как пути файловой системы. Логи HTTP не содержат текста DOCX.

## Развёртывание и проверка

Установить обновлённые зависимости pyproject.toml/requirements.lock (python-docx,
lxml), выполнить `alembic -c apps/delta-core/alembic.ini upgrade head`, собрать
Control Center `npm run build` и перезапустить Core/UI. Схема совместима с
существующими клиентами Agent, обновление desktop для DOCX не требуется.

Тесты `tests/test_documents.py` проверяют загрузку/таблицы, версии, скачивание,
чужого владельца, конфликт записи, изменение только document.xml, формат первого
фрагмента, ограничение выбора для ИИ, отказ неизвестным командам, повреждённые
файлы, DTD и лимит chunked-запроса. Общий backend suite: 243 passed; frontend unit:
6 passed; production build проходит. В браузере на рабочей Delta проверены загрузка, вопрос к OpenRouter, предложение ИИ,
подтверждение с созданием версии 2, ручная правка таблицы в версии 3, чтение исходника
и скачивание. Исходник совпал побайтно, остальные ZIP-части сохранились. Три версии
отрендерены bundled LibreOffice и проверены визуально. Тестовый файл и временная
сессия удалены. Проверка lock-файла uv lock --check прошла.
