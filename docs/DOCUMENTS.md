# Документы DOCX

Раздел «Документы» в Control Center — читалка и мини текстовый процессор для
Word (.docx до 10 МБ). Документ открывается в режиме чтения на светлом листе;
кнопка «Редактирование» включает ввод прямо на странице. Можно создать новый файл,
открыть существующий, скрыть библиотеку и помощника, найти текст и изменить масштаб.

Панель поддерживает полужирный, курсив, подчёркивание, шрифт, размер 6–96 pt
(в панели — обычные размеры), выравнивание, заголовки и стили списков, если эти стили
есть в исходном документе. Enter добавляет абзац на месте курсора; обычные действия
с текстом объединяют/удаляют абзацы. Ctrl+B/I/U, Ctrl+Z, Ctrl+Shift+Z и Ctrl+S работают.
Undo/redo относится к текущим несохранённым правкам; после сохранения доступна история
версий. Отображаются число слов, состояние сохранения и понятные сообщения ошибок.
При уходе с несохранёнными изменениями есть подтверждение; скачивание доступно после
сохранения. Каждая запись создаёт новую неизменяемую версию; оригинал остаётся доступен.

Основной текст, обычные таблицы и встроенные PNG/JPEG/GIF/WebP отображаются на странице.
В простых таблицах редактируется текст, но не структура строк/столбцов. Внешние ресурсы
не загружаются; на встроенные превью выделен общий бюджет 6 МБ. Иллюстрации и сложные
встроенные объекты защищены от правок. Объекты без браузерного превью помечаются как
доступные в скачанном Word. Точное разбиение на печатные страницы, разметка объединённых
ячеек и колонтитулы не воспроизводятся: читалка показывает непрерывный лист. Сложные
таблицы, поля, гиперссылки, секции, content controls, отслеживаемые изменения и неподдержанные
параметры фрагментов доступны только для чтения. Они сохраняются в DOCX.

ИИ отвечает на вопросы по документу и предлагает изменения. Пользователь выбирает
текст обычным выделением мышью/клавиатурой (ИИ получает содержащие его абзацы); без выделения отправляется весь основной текст. Предел контекста
16 000 символов с разметкой: большие документы требуют выделить меньший фрагмент.
В запрос не включаются чужие документы, история общего чата, изображения,
колонтитулы и примечания. Содержимое документа считается данными, а не инструкциями.
Запрос использует текущий provider Delta (OpenRouter, local или auto через bridge).
Интерфейс предупреждает о передаче текста облачной модели. Сам файл не передаётся
LLM. Ответ модели не сохраняет файл: сначала отображается «Было / Станет», затем
пользователь нажимает «Применить и сохранить». Предложения можно отклонить.

Предложения проходят отдельный ToolRegistry с единственным инструментом
`documents.propose_changes`, Pydantic-валидацию, проверку выбранных абзацев и
совпадения исходного текста. Shell, пути и глобальные инструменты не доступны.
Редактирование по ИИ поддерживает только выделенные текстовые абзацы и добавление
текста в конце; длинные ответы ограничены лимитом настроенной модели. Ошибку или
некорректный ответ нужно исправлять новым более узким запросом; файл не меняется.

При сохранении изменяется только word/document.xml. Остальные ZIP-части DOCX
остаются побайтно прежними (изображения, стили, колонтитулы, relationships).
Ручное сохранение форматированного текста сохраняет поддерживаемые свойства каждого
фрагмента: bold/italic/underline/strike, шрифт, размер и RGB-цвет, а также стиль и
выравнивание абзаца. Неизменённые абзацы не переписываются. Новые абзацы привязаны к
соседнему исходному абзацу или таблице; сохраняется порядок содержимого и размещение
в ячейках. Изменение структуры таблиц и перемещение исходных блоков перетаскиванием
не поддерживаются и блокируются. Пустой Word-файл тоже можно начать редактировать.
Старый текстовый API и правки ИИ сохраняют прежнее поведение: изменённый абзац получает
формат первого фрагмента. Поэтому правки ИИ могут упростить смешанное оформление;
ручное форматирование работает через отдельный API. Перед применением ИИ-предложения
всё ещё показывается сравнение «Было / Станет».

## Хранение и доступ

Таблицы Core `documents` и `document_versions` создаёт миграция 0007. Данные и
версии хранятся в базе Core; границы базы Tasks не пересекаются. В режиме аккаунтов
доступ ограничен владельцем документа и существующими admin-сессиями. В dev-режиме
используется существующий bearer-token и общий владелец development. Обновление
ревизии — атомарный UPDATE с проверкой старого номера; конфликт возвращает 409.
Резервная копия Core DB включает все версии; отдельно копировать файлы не нужно.
Удаление документов и квоты хранения пока отсутствуют: учитывайте рост базы.

## API

- GET /api/v1/documents — документы текущего владельца (последние 200).
- POST /api/v1/documents — multipart file (.docx).
- POST /api/v1/documents/blank — JSON name; создать пустой DOCX.
- PATCH /api/v1/documents/{id} — name, base_name; переименовать без новой версии содержимого.
- POST /api/v1/documents/{id}/copy — name, revision; отдельный документ из выбранной версии, HTTP 201.
- GET /api/v1/documents/{id}?revision=N — текст, список версий и rich (paragraphs/layout/styles).
- GET /api/v1/documents/{id}/download?revision=N — DOCX.
- PUT /api/v1/documents/{id} — base_revision, edits[{block_id,old_text,text}], append[].
- PUT /api/v1/documents/{id}/content — base_revision, edits с runs/style/alignment,
  insertions[{anchor,side,paragraphs}], delete[]. Anchor — исходный pN/tN; null добавляет в конец основного текста.
- POST /api/v1/documents/{id}/ask или /propose — revision, instruction, block_ids[].

Документы ограничены 2000 ZIP-частями, 40 МБ распакованного содержимого и 10 000
абзацами. До multipart/JSON-парсинга действует предел HTTP body, включая chunked.
Зашифрованные архивы, макросы, встроенные объекты, XML DTD/entities и дубликаты
ZIP-частей отклоняются. Внешние ресурсы документа не загружаются. Имена файлов
не используются как пути файловой системы. Логи HTTP не содержат текста DOCX.

## Развёртывание и проверка

Установить обновлённые зависимости pyproject.toml/requirements.lock (python-docx,
lxml), выполнить `alembic -c apps/delta-core/alembic.ini upgrade head`, собрать
Control Center `npm run build` и перезапустить Core/UI. Схема совместима с
существующими клиентами Agent, обновление desktop для DOCX не требуется.

Тесты `tests/test_documents.py` проверяют загрузку/таблицы, версии, скачивание,
чужого владельца, конфликт записи, изменение только document.xml, формат первого
фрагмента, ограничение выбора для ИИ, отказ неизвестным командам, повреждённые
файлы, DTD и лимит chunked-запроса. Общий backend suite: 243 passed; frontend unit:
6 passed; production build проходит. В браузере на рабочей Delta проверены загрузка, вопрос к OpenRouter, предложение ИИ,
подтверждение с созданием версии 2, ручная правка таблицы в версии 3, чтение исходника
и скачивание. Исходник совпал побайтно, остальные ZIP-части сохранились. Три версии
отрендерены bundled LibreOffice и проверены визуально. Тестовый файл и временная
сессия удалены. Проверка lock-файла uv lock --check прошла.

## Мини текстовый процессор — проверка 2026-11-19

Используется [Tiptap React](https://tiptap.dev/docs/editor/getting-started/install/react),
с локальными расширениями для идентификаторов Word, защиты объектов и patch-сохранения.
Редактор загружается отдельным JS-модулем при входе в раздел. Файлы не передаются
стороннему редактору или сервису конвертации. Новых миграций БД не требуется.

Проверены backend version/owner/conflict, форматирование фрагментов, вставка/удаление
абзацев, текст таблиц, пустой документ, вставка до таблицы и неизменность остальных
ZIP-частей. В браузере на отдельной SQLite/test-сессии проверены чтение, выделение,
полужирный 16 pt, Enter, Ctrl+S, редактирование таблицы и Ctrl+Z, создание нового файла.
Обнаруженная ошибка блокировки ввода после разделения абзаца исправлена; добавлен
регрессионный тест для назначения нового ID после Enter, повторный browser check прошёл.
Скачанная версия открыта через python-docx; проверены фрагменты текста/форматирование,
изображения, стили, колонтитулы. Сохранённый DOCX отрендерен bundled LibreOffice и
единственная страница проверена визуально: без обрезания/наложения текста.

Итоговая проверка этой версии: 278 backend tests, 14 frontend tests, TypeScript
и production build прошли. Production зависимости: npm audit --omit=dev — 0.
Поиск проверен в read-only режиме для фразы, пересекающей несколько фрагментов
форматирования. Обновление установлено на локальную Delta; Core/Tasks/UI healthy.

## Переименование и копии — 2026-11-19

Откройте документ: в панели «Мои документы» доступны «Переименовать» и
«Создать копию». Название вводится в общем диалоге; расширение .docx добавляется
автоматически. Escape отменяет диалог, Tab удерживает фокус внутри, после закрытия
фокус возвращается к кнопке. Пути, пустые имена и управляющие символы отклоняются.

Переименование меняет только метаданные. Текст, несохранённые правки в редакторе
и история сохраняются. API сравнивает base_name с текущим названием: устаревшая
вкладка получает 409 вместо перезаписи чужого изменения. Содержимое по-прежнему
защищено отдельной проверкой base_revision. Одинаковые названия у разных документов
разрешены; идентификаторы остаются уникальными.

Копия получает новый ID и собственную историю с версии 1. Копируется именно
открытая сохранённая версия: весь DOCX побайтно, включая колонтитулы, изображения
и объекты, которые редактор не отображает. Исходная история не дублируется.
Для возврата к старому содержимому откройте «Историю версий», выберите версию
и нажмите «Создать копию этой версии». Исходник при этом не перезаписывается.
Если есть несохранённые правки, создание копии недоступно с объяснением — сначала
сохраните документ. Обе операции доступны только владельцу; новых LLM-запросов нет.

Проверено: 288 backend / 14 frontend tests, TypeScript и production build.
Новые тесты проверяют права владельца, отсутствие мутаций при неверном имени/версии,
конфликт названия, неизменность истории, побайтную копию старой версии и её независимое
редактирование. В Chromium с отдельной SQLite-базой пройдены переименование,
переименование с несохранёнными правками, запрет копирования до сохранения,
копия исторической версии, валидация имени и возврат фокуса после Escape.
Скачанная browser-created копия побайтно совпала с выбранной версией.

При browser QA исправлен сбой переключения из редактирования к исторической
версии: React-effect обращался к DOM уже уничтоженного Tiptap editor. Теперь
ARIA-атрибут задаётся через editorProps, а effect проверяет isDestroyed.
Повторный сценарий смены версии и копирования прошёл без JavaScript-ошибок;
диалог и страница осмотрены на скриншотах 1366×850.

Локальные замеры на тестовом документе с иллюстрацией, 5 запросов на операцию:
переименование — медиана 41 мс, максимум 52 мс; копия — медиана 168 мс,
максимум 194 мс. Это HTTP round trip к тестовому localhost/SQLite, не нагрузочный
тест и не обещание таких же задержек для максимальных файлов или удалённой сети.

Установлено в работающую Delta; Core/Tasks/UI отвечают HTTP 200, новые API видны
в OpenAPI, systemd user unit активен. Сборка заменена с резервной копией старого
dist и сохранением downloads. Порт 5173 свободен. Vite по-прежнему предупреждает
о размере лениво загружаемого модуля документов (~507 КБ); это не ошибка сборки.
