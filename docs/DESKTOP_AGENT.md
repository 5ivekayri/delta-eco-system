# Delta Agent: настольное приложение

На каждом управляемом компьютере нужно установить Agent. Само открытие сайта
не регистрирует устройство. Сервер Core и клиент Agent — отдельные приложения.
Собранному клиенту не нужны Python, Docker или доступ к базам данных.

## Подключение

1. macOS: откройте DMG, перенесите Delta Agent.app в Applications и запустите.
   Windows: распакуйте всю папку из ZIP; Linux: распакуйте tar.gz с сохранением
   symlink в постоянный каталог и запустите executable.
2. Введите только логин и пароль и нажмите «Войти». В этой LAN-сборке сервер
   по умолчанию — `http://192.168.0.28:8081`; другой адрес задаётся через «Настройки».
3. После входа доступны две вкладки: «Ассистент» (текстовый чат и выбор компьютера)
   и «Устройства» (реальные статусы, обновление каждые 15 секунд).
4. Сервер, имя компьютера, разрешённые папки/приложения, автозапуск и выход из
   аккаунта находятся в отдельном окне «Настройки». Диагностика раскрывается отдельно.
   Сохранение разрешений переподключает агент; смена сервера требует нового входа.
   По умолчанию доступны информация об устройстве и запуск установленных приложений с подтверждением на клиенте.

Чат обращается к тому же Assistant Core, что и веб-интерфейс; команды не повторяются
автоматически после сетевой ошибки. Диалог текущего окна очищается при выходе.
История и голосовой интерфейс остаются доступны в веб-приложении; в нативной
вкладке пока только текст. Существующие разрешения и UID сохраняются при обновлении.

HTTP(S)-адрес сайта преобразуется в WS(S) `/core/ws/agents`.
Для прямого Core используйте полный `ws://HOST:8000/ws/agents`.
Для внешней сети нужен HTTPS/WSS; HTTP/WS — только для доверенной LAN.
Протокол Core не изменяется, gateway должен проксировать WebSocket Upgrade.

## Разрешения и работа в фоне

Клиент проверяет действие, приложение и каталог повторно, даже после проверок
сервера. Symlink за пределы разрешённой папки отклоняется. Разрешены только
каталоги; файлы и произвольные исполняемые пути не запускаются. Agent обнаруживает установленные приложения в стандартных каталогах ОС.
В Settings можно отключить «Открывать установленные приложения»; политика open_app
deny/ask/allow сохраняется. Браузер и VS Code также поддерживают прежние логические ID.
Ни shell, ни Python evaluation, ни доступ к чужим credentials не предусмотрены.

Чтобы изменить разрешения, отключитесь, измените настройки и подключитесь заново.
Закрытие окна оставляет клиент в трее, если трей доступен. Меню Δ позволяет
открыть окно, отключиться или завершить приложение. Без трея закрытие завершает клиент.
Переподключение использует паузу до 30 секунд и прежний UID; действия не повторяются.
Второй экземпляр desktop-клиента блокируется QLockFile. Старый CLI-клиент имеет
отдельную конфигурацию и автоматически не заменяется.

Автозапуск включается явно: macOS LaunchAgent, Windows HKCU Run, Linux XDG autostart.
Это запуск при входе в графическую сессию пользователя, не системный сервис.
После переноса установленного приложения повторно сохраните настройку автозапуска.
Ограничения ОС на доступ к каталогам не обходятся: отсутствие прав возвращает
`LOCAL_PERMISSION_REQUIRED`. GUI-действия требуют пользовательской графической сессии.

На проверенном Mac открытие проекта внутри Desktop сначала задерживалось в
LaunchServices. После подтверждения пользователем системного доступа повторная
команда через Linux Core успешно открыла папку проекта (HTTP 200,
`success=true`). В установленном клиенте разрешены `~/Delta Workspaces` и
`~/Desktop/prog/delta-eco-system`. Другие папки добавляются через окно агента.
`ACTION_TIMEOUT` означает отсутствие подтверждения ОС; автоматического повтора нет.

Настройки и отзываемая сессия (пароль не сохраняется): `~/.delta-agent-desktop/settings.json`, стабильный UID — рядом.
POSIX: атомарная запись, файл 600, новый каталог 700. Windows: ACL профиля пользователя.
Токен пока хранится **без шифрования в keychain**, скрыт в окне и не выводится в ошибки.
API-ключ OpenRouter и пароли БД клиенту не передаются. Для удаления отключите
автозапуск, завершите клиент и удалите приложение; настройки удаляются отдельно.

## Сборка

Собирать на целевой ОС, Python 3.12+, в отдельном окружении:

```sh
python -m venv .agent-build
# Активируйте окружение своей ОС
python -m pip install -r requirements-agent-build.txt
python scripts/check_agent_desktop.py
python scripts/build_agent.py
```

Результат: `dist/agent/Delta-Agent-macOS.dmg`, ZIP Windows или tar.gz Linux.
PyInstaller включает Python, Qt и минимальные зависимости клиента. `.env`,
пользовательские настройки и серверные модули в сборку не входят.
Для запуска из исходников установите также проект: `pip install -e .`, затем
`python -m delta_agent.desktop`. Старый CLI `delta_agent.main` остаётся доступен.

Ручной workflow `.github/workflows/agent-desktop.yml` собирает пакеты на трёх ОС.
Его наличие не подтверждает успешную сборку Windows/Linux: результаты фиксируются
в IMPLEMENTATION_CHECKLIST.md. Пакеты не подписаны Developer ID/Authenticode и не
нотарифицированы; публичный релиз требует подписи и проверки на целевых ОС.
Qt/PySide распространяется как динамические библиотеки; при распространении
сохраняйте лицензии зависимостей.

## Приёмка

Регистрация, heartbeat, переподключение с тем же UID, disconnect→offline,
запуск разрешённого приложения, открытие разрешённой папки и отказ вне неё.
Mock-тесты адаптеров не заменяют реальную проверку на Windows/macOS/Linux.
Проверенные результаты и ограничения: IMPLEMENTATION_CHECKLIST.md.

Вход и роли: [ACCOUNTS.md](ACCOUNTS.md). Кнопка выхода отзывает сессию;
отключение сохраняет её для повторного подключения. Иконка приложения и установщика — Δ.


## Палитра Delta

Веб-интерфейс и настольный клиент используют только чёрный, белый и нейтральные
оттенки серого. Это относится к логотипу и иконке, входу/регистрации, кнопкам,
выделению текста, фокусу, чату, голосовой анимации, настройкам и диагностике.
Статусы и ошибки различаются текстом и формой, а не цветными акцентами.

## Подтверждения команд

В «Настройки → Команды и доступ» доступны режимы «С подтверждениями» (по умолчанию)
и «Полный доступ». Для каждого действия — сведения о компьютере, ссылки, папки,
приложения — можно выбрать правило общего режима, запрет, запрос подтверждения
или разрешение без запроса. Явное правило важнее общего режима. Ссылки у нового
клиента выключены; ранее выбранные приложения и папки сохраняются.

«Полный доступ» относится только к зарегистрированным действиям в пределах
выбранных папок и приложений. Он не даёт терминал, произвольный исполняемый путь
или доступ ко всему диску. Изменения применяются кнопкой «Сохранить настройки»:
агент переподключается с обновлёнными возможностями, ожидающие запросы отменяются.

Диалог на целевом ПК показывает точную ссылку, папку или приложение. «Разрешить
один раз» относится только к этому запросу. «Отклонить», закрытие, 60 секунд без
ответа и отключение не разрешают действие. Heartbeat продолжает работать во время
ожидания. Просроченные запросы не выполняются, очередь ограничена 16 запросами.
Минимальные сведения для регистрации устройства передаются независимо от запрета
команды запроса сведений. Для временных меток срока действия часы клиента и сервера
должны быть синхронизированы.
