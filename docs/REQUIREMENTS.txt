1. Главная идея Delta
Пользователь может работать на разных устройствах:
	•	Windows;
	•	macOS;
	•	Linux;
	•	в будущем Raspberry Pi.
На каждом компьютере работает небольшой Delta Agent.
Есть центральное ядро:
Delta Core.
Пользователь взаимодействует с системой:
	•	голосом;
	•	текстом;
	•	через Delta Control Center.
Delta должна воспринимать сервисы и устройства как единую экосистему.
Примеры пользовательских команд:
«Какие компьютеры сейчас подключены?»
«Открой диплом на MacBook.»
«Добавь задачу протестировать API до пятницы.»
«Покажи задачи по дипломной работе.»
«Открой рабочее пространство Dark Weather на этом компьютере.»
«Включи рабочий свет.»
В будущем:
«Какая завтра погода?»
«Продолжим проект на другом компьютере.»
«Когда я начинаю работать вечером, включай рабочий режим.»
«Найди документ, где я описывал MQTT.»

2. Какую проблему решает Delta
У пользователя рабочий контекст разбросан между:
	•	разными компьютерами;
	•	разными ОС;
	•	приложениями;
	•	файлами;
	•	задачами;
	•	веб-сервисами;
	•	IoT-устройствами;
	•	внешними API.
Для продолжения работы пользователь вручную:
	•	открывает нужный компьютер;
	•	ищет папки;
	•	запускает приложения;
	•	открывает сайты;
	•	вспоминает задачи;
	•	переключается между сервисами.
Delta должна создать единый слой управления поверх существующих систем.
Главная идея:
пользователь задаёт намерение естественным языком, а Delta выбирает устройство, сервис и действие.

4. Архитектурный принцип
LLM НЕ содержит бизнес-логику.
LLM не работает напрямую:
	•	с PostgreSQL;
	•	с файловой системой;
	•	с shell;
	•	с Task DB;
	•	с устройствами.
LLM только выбирает разрешённый Tool.

«Добавь задачу протестировать API.»

arguments:

↓

↓
Delta отвечает пользователю.

20. Delta Agent Responsibilities
При запуске Agent:
	1	загрузить config;
	2	определить OS;
	3	определить architecture;
	4	определить hostname;
	5	определить capabilities;
	6	подключиться к Delta Core;
	7	зарегистрировать Device;
	8	поддерживать WebSocket;
	9	отправлять heartbeat;
	10	принимать command;

	13	возвращать structured result.

22. Security Delta Agent
КРИТИЧЕСКИ ВАЖНО.
Никаких:
execute_shell(command)
run_python(code)
eval()
exec()
remote arbitrary command.
Нельзя разрешать LLM выполнять произвольные shell-команды.
Agent работает только через predefined capabilities.

	4	зарегистрировать tools;
	5	добавить service config.
После этого Assistant должен иметь возможность использовать:
weather.current
weather.forecast.
Если для этого приходится серьёзно переписывать Delta Core, архитектура неправильная.

118. Финальная цель MVP
Delta v0.1 должна доказать:
один пользователь может управлять своими компьютерами и независимыми сервисами через единый голосовой и текстовый AI-интерфейс, а архитектура позволяет постепенно подключать новые цифровые и физические сервисы без переписывания ядра.
Delta должна восприниматься не как voice bot, а как основа персональной цифровой экосистемы.

119. Перед началом разработки
Сначала:
	1	изучи текущий repository;
	2	если repository пустой — создай структуру;
	3	создай docs/ARCHITECTURE.md;

	5	создай AGENTS.md;

При выборе между сложным и простым решением выбирай минимально сложное решение, которое сохраняет:
	•	cross-platform;
	•	service extensibility;
	•	Tool Calling;
	•	Voice;
	•	Security;
	•	будущий Raspberry Pi;
